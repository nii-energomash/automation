# Настройки проекта

Конфиги, которые читает инструмент сборки в репозитории-потребителе. От
`ci-src/` они отличаются тем, что работают и без CI: обычный `npm install` на
машине разработчика читает их ровно так же, как прогон на раннере. Поэтому они
лежат здесь, а не рядом с воркфлоу и экшенами.

Уровень внутри — профиль проекта. Сегодня он один:

- `npm/` — проектный `.npmrc` и сторож при `package-lock.json`.

Профиль `nuget` не заведён: `nuget.config` и `Directory.Build.props`, которые
лежат в корне у dotnet-проектов, сюда не переносились.

Путь назначения из пути здесь не выводится: правило совпадения путей действует
только внутри `ci-src/`. Правду говорят строка `# место:` в шапке файла и
[docs/copy-map.md](../docs/copy-map.md).

Зачем эти файлы нужны и что без них ломается — в [docs/npm.md](../docs/npm.md).
