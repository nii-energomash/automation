# Экшены

Композитные действия двух видов: общие для обеих площадок и площадочные.
Входы, умолчания и выходы описаны в самом `action.yml` — здесь только
назначение и то, чего в файле не видно.

## Общие для GitHub и Gitea

Лежат в [`ci-src/.ci/actions/`](../ci-src/.ci/actions), копируются каталогом
целиком в `.ci/actions/<name>/` репозитория-потребителя и вызываются оттуда как
`uses: ./.ci/actions/<name>`.

### `prepare-npm-release`

Проставляет версию из git-тега в `package.json` и выбирает dist-тег
публикации: `next` для предварительного релиза, `latest` для старшего тега,
`lts-vN` для патча линии сопровождения. Вызывается из `publish.yml` npm-набора
до `npm publish`.

Вход `manifest-dir` нужен, когда `package.json` лежит не в корне:
`defaults.run.working-directory` уровня job на шаги композитного действия не
распространяется.

Префикс `lts-`, а не суффикс `-lts`: имя вида `v3-lts` реестр Gitea читает как
версию `3.0.0-lts` и отвергает — причём уже приняв tarball, то есть пакет
опубликован, а прогон красный.

### `prepare-nuget-release`

Сверяет формат релизного тега и отдаёт номер версии для `-p:Version`. Рабочую
копию не правит: версия в проекте не хранится, её получает `dotnet build/pack`
из аргумента. Вызывается из `publish.yml` NuGet-набора.

### `version-from-tag`

Сверяет формат git-тега и отдаёт версию сервиса для образа. Вызывается из
`release.yml` docker-набора.

## Площадочные экшены

Лежат в [`ci-src/.github/actions/`](../ci-src/.github/actions) и
[`ci-src/.gitea/actions/`](../ci-src/.gitea/actions), копируются каталогом
целиком в `.github/actions/<name>/` и `.gitea/actions/<name>/`. В `.ci/`
они не попадают не по недосмотру: каждый обращается к API или окружению одной
площадки, и второй не пригодится вовсе.

### `registry-cleanup` — по экземпляру на площадку

Удаляет из реестра технические образы старше указанного возраста. Вызывается
из `registry-cleanup.yml` docker-набора. Экземпляры разные, потому что API
разное: у GitHub это `gh api` по версиям пакета репозитория, у Gitea —
собственный API пакетов, которому нужны адрес инстанса, владелец и имя пакета
входами.

### `docker-cli` (Gitea)

Ставит docker CLI и плагин buildx, если их нет в образе задания. Демон не
ставится: задание работает с демоном хоста через проброшенный сокет. Пакета
`docker-ce-cli` в дистрибутиве нет, а `docker.io` притащил бы второй демон,
поэтому берётся статическая сборка. Площадке GitHub экшен не нужен вовсе —
там docker приходит с раннером, а buildx ставит `docker/setup-buildx-action`.

Плагин нужен проекту, чья сборка тянет зависимости из внутреннего реестра:
токен уезжает в неё секретом BuildKit, а `RUN --mount=type=secret`
классический сборщик не умеет. Проекту без таких зависимостей вторая половина
скрипта не нужна, см. [docker.md](docker.md).

### `release-upload` (Gitea)

Прикрепляет файлы к релизу по его тегу — то, что на GitHub делает одна команда
`gh release upload`. Нужен заданию `archive`, которое собирается на стороне
проекта, см. [docker.md](docker.md).

### `nuget-sources` (Gitea)

Собирает файл источников NuGet под реестр Gitea и кладёт его в рабочее дерево.
Файл собирается на раннере, а не лежит в репозитории, потому что адреса
инстанса в репозитории нет вовсе: он приходит переменной. Список полный,
включая `nuget.org` и маппинг для него, — файл, переданный через
`--configfile`, заменяет всю цепочку конфигов, а не дополняет её. Токен в файл
не попадает: он раскрывается из `GT_PACKAGES_TOKEN` в момент восстановления.

Вход `patterns` — маски пакетов, которые берутся из реестра Gitea, по одной в
строке. Это единственное, что правится под проект.

## Общие решения

Каталог `.ci/actions/` не привязан к площадке: обе площадки читают экшен по
относительному пути из рабочего каталога, поэтому одна копия обслуживает оба
зеркала и не даёт им разъехаться.

Формат тега (`^v[0-9]+\.[0-9]+\.[0-9]+$`) вынесен во вход с умолчанием, а не
захардкожен: это политика, которая обязана совпадать у GitHub и Gitea, и
меняется она в одном месте.

Скрипт вызывается как `bash "$GITHUB_ACTION_PATH/run.sh"`, а не как
`./run.sh`: так не нужен бит исполнения, который Windows не проставит.
