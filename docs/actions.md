# Экшены

Композитные действия, общие для GitHub и Gitea. Лежат в
[`ci-src/.ci/actions/`](../ci-src/.ci/actions), копируются каталогом целиком
в `.ci/actions/<name>/` репозитория-потребителя и вызываются оттуда как
`uses: ./.ci/actions/<name>`.

Входы, умолчания и выходы описаны в самом `action.yml` — здесь только
назначение и то, чего в файле не видно.

## `prepare-npm-release`

Проставляет версию из git-тега в `package.json` и выбирает dist-тег
публикации: `next` для предварительного релиза, `latest` для старшего тега,
`lts-vN` для патча линии сопровождения. Вызывается из `publish.yml` npm-набора
до `npm publish`.

Вход `manifest-dir` нужен, когда `package.json` лежит не в корне:
`defaults.run.working-directory` уровня job на шаги композитного действия не
распространяется.

Префикс `lts-`, а не суффикс `-lts`: имя вида `v3-lts` реестр Gitea читает как
версию `3.0.0-lts` и отвергает — причём уже приняв tarball, то есть пакет
опубликован, а прогон красный.

## `prepare-nuget-release`

Сверяет формат релизного тега и отдаёт номер версии для `-p:Version`. Рабочую
копию не правит: версия в проекте не хранится, её получает `dotnet build/pack`
из аргумента. Вызывается из `publish.yml` NuGet-набора.

## `version-from-tag`

Сверяет формат git-тега и отдаёт версию сервиса для образа. Вызывается из
`release.yml` docker-набора.

## Общие решения

Каталог `.ci/actions/` не привязан к площадке: обе площадки читают экшен по
относительному пути из рабочего каталога, поэтому одна копия обслуживает оба
зеркала и не даёт им разъехаться. Площадочный экшен, если такой появится,
ляжет в `ci-src/.github/actions/` или `ci-src/.gitea/actions/`.

Формат тега (`^v[0-9]+\.[0-9]+\.[0-9]+$`) вынесен во вход с умолчанием, а не
захардкожен: это политика, которая обязана совпадать у GitHub и Gitea, и
меняется она в одном месте.

Скрипт вызывается как `bash "$GITHUB_ACTION_PATH/run.sh"`, а не как
`./run.sh`: так не нужен бит исполнения, который Windows не проставит.
