# Правила оформления

## Правило копирования

Путь внутри `ci-src/` совпадает с путём в корне репозитория-потребителя.
Исключение одно: сегмент типа проекта (`npm/`, `nuget/`, `docker/`) при
копировании выбрасывается — на один целевой `.github/workflows/ci.yml`
претендуют три разных источника.

```
ci-src/.github/workflows/npm/ci.yml   →  .github/workflows/ci.yml
ci-src/.ci/actions/version-from-tag/  →  .ci/actions/version-from-tag/
```

Экшены и всё остальное копируются один в один.

Исключение забывается ровно так же, как забылось бы переименование файла,
поэтому записано в трёх местах: в шапке самого файла, в `README.md` каталога
типа и в [copy-map.md](copy-map.md).

Обратное — два файла на один целевой путь — встречается ровно раз:
`ci-python.yml` и `ci-dotnet.yml` docker-набора оба претендуют на `ci.yml`
потребителя, и берётся тот, что подходит языку проекта. Строка `# место:` у
них поэтому одинаковая, а выбор оговаривается отдельной строкой шапки.

## Шапка копируемого файла

Первые строки каждого файла под `ci-src/` — две строки комментария, которые
уезжают вместе с копией:

```yaml
# источник: nii-energomash/automation/ci-src/.github/workflows/npm/ci.yml
# место: .github/workflows/ci.yml
```

`# источник:` отвечает на «откуда это взялось и с чем сверять», `# место:` —
на «куда это положить». Обе видны в момент вставки, а не до него, и остаются
в репозитории-потребителе.

Строка `# место:` ставится и там, где путь совпадает один в один: правило
должно быть единым, иначе приходится помнить, где исключение, а где нет.

В скрипте шапка идёт после шебанга, отдельной строки между ними нет.

В `action.yml` шапка идёт после строки `# yaml-language-server:`: модлайн
обязан остаться первой строкой документа, иначе редактор не подтягивает схему.
Между модлайном и шапкой — пустая строка.

## Ссылки на issue

В копируемые файлы ссылки на issue не ставятся. Номер верен только в том
репозитории, где задача заведена: и здесь, и в любой копии тот же `#127`
указывает уже на чужую задачу. Причина, по которой сделано именно так,
пишется словами.

Отсюда ожидаемое расхождение при сверке с живой копией: там ссылка может
остаться, здесь её нет.

## README в каталоге типа

У каждого каталога типа (`ci-src/.github/workflows/npm/` и остальных) есть
`README.md` с одной фразой о том, куда кладутся его файлы. Это второе место,
где записано исключение из правила копирования.

## Именование

Файлы набора называются одинаково на обеих площадках и во всех типах:

| Файл                   | Что делает                                   |
| ---------------------- | -------------------------------------------- |
| `ci.yml`               | сборка и проверки по `push`                  |
| `publish.yml`          | публикация пакета по релизу                  |
| `publish-sha.yml`      | публикация образа с техническим тегом по SHA |
| `release.yml`          | публикация образа по релизному тегу          |
| `registry-cleanup.yml` | чистка реестра по расписанию                 |

Каталог экшена называется по действию, без префикса площадки:
`prepare-npm-release`, `version-from-tag`.

## Источник содержимого

Содержимое приезжает **из живого репозитория**, а не пишется здесь с нуля.
Референс отражает то, что уже работает; файл, которого никто не прогонял,
здесь не место.

Отсюда и порядок сверки: скопировать файл из `ci-src/` поверх копии в
исходном репозитории и убедиться, что `git diff` пуст с точностью до шапки.
Непустой diff означает, что перенесли не то, что работает.

Обратного автоматического пути нет: правка здесь до копий не доезжает, и
наоборот. Расхождение видно только этой сверкой.

## Что не коммитится

Репозиторий публичный, поэтому внутреннее попадает сюда только
плейсхолдерами:

- токены, пароли, ключи и файл `.runner` раннера Gitea;
- внутренние адреса и порты — вместо них `<gitea-host>` или переменные
  репозитория (`vars.REGISTRY_HOST`, `vars.REGISTRY_OWNER`);
- имена пользователей, пути на конкретных машинах, имена хостов.

Заслон в `.gitignore` ловит типовые имена файлов, но не содержимое: файл с
адресом внутри проходит мимо него, и вычитка перед коммитом обязательна.

## Формат

- Переводы строк — `LF`, задано в `.gitattributes`.
- Кодировка, отступ в два пробела, перевод строки в конце файла и подрезка
  хвостовых пробелов — в `.editorconfig`; в Markdown хвостовые пробелы не
  подрезаются, там два пробела означают перенос.
- Ширина строки — 80 символов. Держится вручную: инструмента, который бы это
  проверял, в репозитории нет.
